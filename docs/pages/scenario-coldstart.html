Scenario 5 — New seasonal route launch

Network Planning announces JFK-PVG (New York to Shanghai), twice-weekly, starting in 35 days. The route has zero historical data. The Director of RMS wants a forecast anyway. This is the cold-start scenario that justifies the foundation-model approach in the first place.

TL;DR. No history → can't call TimesFM directly (needs ≥32 points of context). Build a 90-day synthetic prior by averaging normalized fare curves from analog routes (JFK-HKG, JFK-NRT, ORD-PVG). Run forecast_with_covariates() on the synthetic prior + real AA covariates. PI is wide for the first 14 days; tightens as real bookings replace synthetic days in the rolling context window. Day-1 MAPE drops from 16% (legacy) to 8% (TimesFM).

Trigger

Network Planning notifies RMS that JFK-PVG launches Mar 15, twice weekly (Tue and Sat). Equipment: 777-300ER. Fare-class structure published. No history. The pricing team needs an opening fare ladder for booking that opens 30 days ahead of departure — so we have ~5 days to produce a credible forecast.

The fundamental problem

TimesFM (or any context-conditioned forecaster) needs a context window to predict from. Our model expects 90 days of daily fare history per OD-pair. JFK-PVG has zero days. Three classes of solutions:

The synthetic-prior approach

The path we shipped. Three steps:

Step 1: define the analog set

For JFK-PVG, the analogs are routes that share key dimensions:

  • Geography: Asia long-haul from US East/Midwest. JFK-HKG, JFK-NRT, ORD-PVG.
  • Equipment: Wide-body. (Not narrow-body Caribbean.)
  • Cabin mix: Premium-heavy. (Not all-economy.)
  • Frequency: Limited (twice-weekly), not daily. Different booking-curve dynamics.

The analog set has 3 routes. More analogs would smooth more, but we want to capture the specifics of "twice-weekly Asia long-haul from JFK."

Step 2: build the synthetic context

import numpy as np

def build_synthetic_prior(analog_fare_panels, target_route_meta):
    """
    analog_fare_panels: dict[route_id, np.ndarray] of last 90 days of fares
    target_route_meta:  dict with base_fare, route_type, etc.
    Returns: 90-day synthetic fare context for the new route.
    """
    # 1. Normalize each analog by its mean (so they overlay despite different fare levels)
    normed = {
        rid: panel / panel.mean()
        for rid, panel in analog_fare_panels.items()
    }
    # 2. Average across analogs — gives the typical normalized shape
    synthetic_shape = np.mean(list(normed.values()), axis=0)
    # 3. Scale by the new route's expected base fare (from Pricing's ladder filing)
    synthetic_context = synthetic_shape * target_route_meta["base_fare"]
    return synthetic_context.astype(np.float32)

Step 3: forecast as usual, but flag the synthetic context

point, q = model.forecast_with_covariates(
    inputs=[synthetic_context],
    dynamic_numerical_covariates={"jet_fuel_usd_gal": [fuel], ...},
    static_categorical_covariates={
        "route_type": ["international-asia-longhaul"],
        "cabin": ["mixed"],
        "equipment": ["widebody"],
    },
)

# CRITICAL: widen the PI to reflect synthetic-context uncertainty.
# We empirically inflate q90 by +30% and lower q10 by -30% during the
# first 14 days of the route's life.
SYNTHETIC_PI_INFLATION = 0.30
q[..., 1] -= np.abs(point - q[..., 1]) * SYNTHETIC_PI_INFLATION   # widen q10
q[..., 9] += np.abs(q[..., 9] - point) * SYNTHETIC_PI_INFLATION   # widen q90

The PI inflation is a deliberate over-estimate of uncertainty, conservative by design. Without it, the model would report PIs as if the synthetic context were as informative as real history — and downstream the optimizer would over-trust the q90.

Day-1 forecast quality

On the launch day, the median forecast for JFK-PVG was ~$1,450 main cabin, ~$4,200 business. Realized averages over the first month: $1,510 main, $4,310 business. MAPE on the launch month: 8.1% — well within the network MAPE band. Coverage of 80% PI: 78% — calibrated.

Trade-offs

Analog selection bias

Carefully chosen analogs

  • Capture route-specific dynamics (premium mix, equipment).
  • Day-1 MAPE much better than global mean.

Over-narrow analogs

  • Only 3 routes → high variance in the average.
  • Bias if those 3 routes are seasonally idiosyncratic at the time of borrowing.
  • Solution: average across longer time window (180 d not 90 d) on the analogs to smooth their idiosyncrasy.

How wide should the PI inflation be?

The 30% inflation was set empirically by simulating launches on retired routes — we re-launched a route that had history, used the analog method as if no history existed, and measured how much the PIs needed to widen to maintain calibration. Settled on 30% as the smallest that kept coverage ≥78% in the simulation.

Where this could fail

  1. No good analogs. A truly novel route (e.g., the first Antarctic charter) has no analogs. Fall back to manual fare-setting by Pricing for the first 30 days.
  2. Demand surprise. JFK-PVG launches and demand is 2× what analogs suggested (a sudden China travel boom). The synthetic prior is wrong; the model under-forecasts. Symptom: load factor jumps quickly; revenue management raises bid-prices manually. Model self-corrects within 14 days as real history fades in.
  3. Analog-route disruption. If JFK-HKG was in irrops during the synthetic-prior window, the average is biased low. Mitigation: use 180-day analog windows excluding any flagged irrops periods.
  4. Equipment mismatch. Network Planning swaps the 777-300ER to a 787 mid-launch. Static cabin/equipment covariate would change; we'd re-run with the new static labels but the synthetic prior may need re-derivation if cabin layout differs materially.

Real-world variants

  • Re-launch of seasonal route. AA stops MIA-EZE for summer, restarts in winter. Has prior history but stale (4 months gap). Cold-start lite: use the prior-year same-season history as context.
  • Equipment up-gauge. Same OD-pair, narrowbody → widebody. Static covariate changes but historical fares apply (cabin mix shifts).
  • Frequency increase. Twice-weekly → daily. The DTD distribution shifts because more daily flights mean lower per-flight load factor for the same demand. Forecast adjustment is small but real.
  • Codeshare-only launch. AA sells JV partner's flight as AA-coded. Need different covariate handling because the operator (and equipment) is JV partner, not AA.

Interview Q&A

Why does the foundation-model approach win on cold-start?
Because the foundation model has an implicit prior over time-series shapes from its 100-billion-point pretraining. Per-route ARIMAX has no prior — with zero history it produces a constant or a global mean. TimesFM's prior, even on a synthetic context, gives a reasonable shape. The synthetic prior gives the model the right scale; the foundation prior gives the right shape; the covariates condition on AA-specific structure. Three layers of prior knowledge stacked.
How do you decide what counts as an analog?
Three dimensions: geography (region pair), equipment (narrow vs wide-body), and frequency (daily vs limited). Pricing maintains the analog mapping in a config file; new routes inherit analogs from Network Planning's route-cluster definition. We re-validate annually by simulating cold-start on retired routes. If the analog-set MAPE on simulation is >12%, we expand the set to 5+ analogs.
Could you use hierarchical Bayesian pooling instead?
Yes — conceptually cleaner. Pool across all Asia long-haul routes, estimate route-specific deviations, propagate uncertainty through. Estimated MAPE 9% (slightly worse than synthetic prior on our simulation), but with theoretical PI guarantees. Reason we chose synthetic prior instead: ops simplicity. Synthetic prior is a 30-line function; Bayesian pooling needs PyMC + a re-fit pipeline + uncertainty propagation. For ~12 launches/year the engineering ROI didn't justify it.
Why inflate the PI by 30% and not let the model figure it out?
The model's quantile head was trained on series with real history. When fed a synthetic context, it does NOT know the context is synthetic; it produces PIs as if the context were as informative as real data. The 30% inflation is a post-hoc correction for the input's reduced informativeness. A more principled approach would be to encode "synthetic-ness" as a static covariate and train on simulated cold-start; we tested this but the synthetic-flag training data was hard to construct without leakage. The 30% empirical inflation is the pragmatic answer.
What happens if you have only 14 days of real history? Still cold-start?
Hybrid. Concatenate: 76 days of synthetic + 14 days of real. The model takes the 90-day window. PI inflation tapers from 30% (day 0) to ~0 (day 90) as the synthetic days age out. The model doesn't need a special flag — the real days are simply the most recent in the rolling window, weighted naturally by recency in the attention.
How does this compare to what an LLM would do for a new route?
An LLM would have to be prompted with descriptions of analog routes and asked to predict; it would produce confident-sounding numbers without a real probability distribution. No calibrated uncertainty. The synthetic-prior + foundation-model approach gives both a credible point forecast and calibrated PIs. The LLM gets the prose right; the foundation TS model gets the math right.
