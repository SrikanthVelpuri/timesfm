Adapted Google’s TimesFM 2.5 foundation model to American Airlines pricing data through two cheap surgical fine-tuning surfaces — an XReg regression head and per-route-family LoRA adapters — then optimized inference 47× to fit a single A10G GPU and a $50/year cloud bill. What it does

  • Forecasts daily average fare for 6,700 AA OD-pairs over a 30-day horizon, conditioned on 8 dynamic + 3 static covariates.
  • Returns calibrated quantiles (q10, q90) so the C++ bid-price optimizer can do risk-aware inventory decisions.
  • Trained without continued pretraining — AA has no budget for that — using only XReg head fine-tuning and LoRA adapters.
  • Hot-swaps LoRA adapters per route family in <10 ms with pinned-memory state-dict updates.
  • Falls back gracefully when an adapter fails: head-only forecast, no service degradation.
  • Self-monitoring — PI coverage drift on top-50 routes pages me at 2 a.m. with a one-command rollback path.

TimesFM 2.5 architecture, AA-flavored

200M-parameter decoder-only transformer trained on 100B time-series points by Google. Here is how I plug AA pricing into it.

The pipeline, top to bottom

1

Patching

90 daily fares → 3 patches of 32 points each. Mask-aware; padding flags ride alongside.

2

Input residual MLP

Per-patch z-normalization + 2-layer MLP → 1280-d patch embedding. normalize_inputs=True for AA: fares range $80–$11,000.

3

Transformer trunk (20 blocks)

Causal self-attention with RoPE, SwiGLU FFN, pre-LayerNorm. Frozen for AA — no continued pretraining.

4

Output head

128-step patch + 10-quantile head. fix_quantile_crossing=True — the C++ optimizer requires monotonic quantiles.

5

XReg layer (AA fine-tuned)

Regression on residuals: final = TimesFM_baseline + XReg(future_covariates). This is where AA-specific elasticities live.

6

LoRA adapter (per route family)

Rank-8 adapters on attention Q/K/V/O projections. Hot-swapped per family in <10 ms.

The exact ForecastConfig AA uses

cfg = timesfm.ForecastConfig(
    max_context=90,                        # one quarter of daily fares
    max_horizon=30,                        # 30-day RMS window
    normalize_inputs=True,                 # fares range $80 - $11,000
    per_core_batch_size=64,                # tuned for A10G
    use_continuous_quantile_head=True,     # better long-horizon calibration
    force_flip_invariance=True,            # f(-x) = -f(x)
    infer_is_positive=True,                # fares strictly positive
    fix_quantile_crossing=True,            # required for the optimizer
    return_backcast=False,                 # AA does not need backcast
)

Each flag ties to a specific failure I hit in production backtests. Full incident history in model_architecture.md.

Fine-tuning — cheap, surgical, no pretraining

AA does not have a continued-pretraining budget. The Google base weights stay frozen. Fine-tuning happens on two cheap surfaces: the XReg regression head (~40 min, $0.70) and per-route-family LoRA adapters (~6 hours total, $6.50). Total quarterly compute: ~$7.

MAPE progression

Each fine-tuning stage cuts validation MAPE. Going past LoRA rank-8 to full fine-tune would cost ~$45K to capture the last 0.4 pp — not defensible.

Compute cost per stage

Two-stage path captures >85% of achievable gain at <1% of full fine-tune cost.

The two stages

Stage A — XReg head

  • Trunk frozen; only the regression head trains.
  • Pinball loss across 10 quantiles + median MSE.
  • ~250K windows, 3 epochs, ~40 min on 1×A10G.
  • Output: ~1.2 MB safetensors file.
  • Result: 10.2% → 6.0% MAPE.

Stage B — LoRA adapters

  • Rank-8 LoRA on attention Q/K/V/O.
  • One adapter per route family (20 families).
  • ~50K windows per family, ~6 min each.
  • Output: 17 of 20 ship; 3 fall back to head-only.
  • Result: 6.0% → 5.1% MAPE.

Per-family LoRA pass/fail

Families that did not improve by ≥0.5 pp MAPE fall back to head-only forecast. No service degradation.

Inference optimization — 280 ms → 6 ms

47× speedup, layer by layer. Each optimization is independently rollback-able. Full nightly batch over 6,700 OD-pairs runs in 41 seconds on a single A10G spot instance, $0.011 per run.

Latency by configuration

Each row is a separate change. Batching alone got 80% of the win — the rest was cleanup.

Throughput vs cost

Right-axis cost per nightly run; left-axis throughput. The optimization budget is in dollars, not seconds.

What I tried that did NOT work

  • INT8 dynamic quantization. 4 ms latency, but 80% PI coverage dropped to 73%. Bid-price-grade quantiles couldn’t take the precision hit. Dropped.
  • ONNX + TensorRT. 5% kernel-coverage gap fell back to CUDA, eliminating the speedup. With torch.compile already at 6 ms, not worth the operational complexity.
  • Speculative decoding. TimesFM’s output patches are 128 steps; only 30 are kept. Speculation overhead exceeded savings.
  • Multi-GPU sharding. 1.6× speedup at 2× cost. Doubling cost to halve a 41-second job is bad business.

Six pricing scenarios in production

The same forecast_with_covariates() call serves all six scenarios. The difference between them is entirely in the covariate inputs and the optimizer’s policy — that is the point of the foundation-model approach.

🎄

1. Thanksgiving rush

Holiday flag pre-published; horizon spans Nov 26 → Dec 1. Forecast median jumps +$95, q90 widens to $525. Optimizer protects high-yield inventory; +$11M revenue across the network for the holiday week.

⛽

2. Fuel-price spike

Brent up 9% Monday. jet_fuel_usd_gal covariate updates. XReg coefficient (+$11.4 per $1 fuel) lifts every OD-pair forecast. Off-cycle re-score job fires at 05:00 CST.

📉

3. Competitor undercut

Delta drops fares on ATL-LAX at 06:14 a.m. CST. Competitor covariate updates for adjacent routes. Forecast for ORD-LAS shifts -$17 (0.85 elasticity); optimizer matches on leisure routes only.

🌨️

4. Weather irrops

Winter storm at ORD for two days. weather_disruption flag flips to 1. Forecast drops -$22 on affected days only; surrounding days unaffected. Optimizer dumps low-class inventory.

✈️

5. New seasonal route launch

JFK-PVG launches with zero history. Synthetic prior from analog routes (JFK-HKG, ORD-PVG) + AA covariates. Wide PI for first 14 days; tightens as real bookings come in.

💺

6. Cabin upsell forecast

Premium economy on DFW-LAX. Static cabin covariate flips. Median ~2.6× main-cabin; PI much wider ($600 vs $135). Optimizer protects last-minute upsell inventory.

Frequency of these scenarios

Per-year frequency in real AA operations. Scenarios 2–4 trigger off-cycle re-scoring jobs; scenario 1 is built into the nightly run.
