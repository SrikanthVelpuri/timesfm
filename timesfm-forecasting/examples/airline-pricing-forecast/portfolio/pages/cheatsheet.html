The 30-second pitch

What I built

Took Google's TimesFM 2.5 foundation model and fine-tuned it for AA daily-fare forecasting across 6,700 OD-pairs — without continued pretraining because we had no budget for it. Two PEFT surfaces: an XReg regression head for AA covariate elasticities, and per-route-family LoRA adapters for high-revenue routes. Optimized inference 47× through batching + BF16 + torch.compile + pinned-memory LoRA hot-swap. Deployed on AA's Azure footprint — Azure ML registry, NV A10 v5 spot VMs, Blob Storage, Cosmos DB, AKS, Application Insights, Microsoft Entra ID. Owned end-to-end as the Applied Scientist: data, modeling, eval, deployment, on-call.

Result: network MAPE 10.2% → 5.1%, 80% PI coverage 79.3%, nightly batch 41 s on one Azure NV A10 v5 spot VM, ~$48M estimated annual revenue lift, ~$60/year cloud cost.

Architecture in five steps

  1. Patching: 90 daily fares grouped into 32-point patches (3 patches).
  2. Input residual MLP: per-patch z-normalize + 2-layer MLP → 1280-d patch embedding.
  3. Transformer trunk: 20 blocks, causal self-attention with RoPE, SwiGLU FFN. Frozen for AA — no pretraining.
  4. Output head: 128-step output patch + 10-quantile head (q10..q90). Monotonicity enforced with fix_quantile_crossing=True.
  5. XReg layer (AA fine-tuned): regression on residuals: final = TimesFM_baseline + XReg(future_covariates). + LoRA rank-8 on attention Q/K/V/O per route family.

Fine-tuning in three lines

Stage A: XReg head

  • Frozen trunk; only the regression head trains.
  • Loss: pinball + 0.5 · median MSE.
  • ~250K windows, 3 epochs, ~40 min on A10G, $0.70.
  • Output: ~1.2 MB safetensors. Always loaded.
  • Result: 10.2% → 6.0% MAPE.

Stage B: LoRA per family

  • Rank-8 on attention Q/K/V/O in all 20 blocks.
  • α = 16 (so α/r = 2.0).
  • ~50K windows per family, ~6 min, ~$0.30.
  • 17 of 20 families pass ≥0.5 pp gate.
  • Result: 6.0% → 5.1% MAPE.

Why we passed on full FT

  • Full FT: 4.7% MAPE at $45K/quarter.
  • LoRA r-8: 5.1% MAPE at $7/quarter.
  • Going from 5.1% → 4.7% costs >100× and is not defensible.
  • Foundation prior preserved by frozen trunk.

Rejected approaches

  • INT8 quant — coverage dropped to 73%
  • ONNX + TensorRT — 5% kernel coverage gap
  • Speculative decoding — horizon math doesn't fit
  • Multi-GPU — doubles cost for 1.6× speed

Why batching wins so much

  • GPU tensor cores execute fixed-size tiles (16×16 BF16).
  • Batch=1 leaves most of the tile unused.
  • Batch=64 fully utilizes the tile.
  • Same kernel-launch cost amortized over 64 items.

Math you should be able to write on a whiteboard

Pinball loss (training)

Lτ(y, q̂τ) = max( τ(y − q̂τ),  (τ − 1)(y − q̂τ) )

For τ=0.9 the loss penalizes under-prediction 9× more — pushes q90 high enough.

LoRA decomposition

W' = W + (α/r) · B A, where A ∈ ℝr×k, B ∈ ℝd×r, r << min(d, k)

For a 1280×1280 matrix at rank 8: 20,480 params instead of 1.638 M (~80× reduction).

PSI for data drift

PSI = Σbins ( precent − ptrain ) · ln( precent / ptrain )

PSI < 0.1 stable, 0.1–0.25 watch, > 0.25 investigate.

ECE (expected calibration error)

ECE = Στ ∈ bins | empirical_coverage(τ) − τ |

Sum across 9 quantile bins; release gate ECE ≤ 0.04.

CRPS (approximation)

CRPS ≈ (2/K) Σk=1K Lτk(y, q̂τk)

Average pinball loss across quantiles is a Monte-Carlo CRPS estimate.

3. Pinned-memory LoRA hot-swap

# At service startup
adapters = {}
for family in FAMILIES:
    sd = safetensors.load_file(f"adapters/{family}.safetensors")
    adapters[family] = {k: v.pin_memory() for k, v in sd.items()}

# Per batch
if family != current_family:
    with torch.no_grad():
        for k, v in adapters[family].items():
            model.get_parameter(k).copy_(v, non_blocking=True)
    torch.cuda.synchronize()
    current_family = family

4. The eval harness in 30 lines

def evaluate(model, dataset):
    point, q = model.forecast_with_covariates(...)
    y = np.asarray(dataset["actuals"])
    yhat = point
    q10, q90 = q[..., 1], q[..., 9]

    mape  = np.mean(np.abs(y - yhat) / np.abs(y)) * 100
    cov80 = np.mean((y >= q10) & (y <= q90)) * 100

    levels = np.arange(1, 10) / 10.0
    ece = sum(abs(np.mean(y <= q[..., k+1]) - tau)
              for k, tau in enumerate(levels))

    return {"mape": mape, "coverage_80pct": cov80, "ece": ece}

Killer Q&A — one per deep-dive page

Why TimesFM and not [Prophet/DeepAR/LLM/etc]?
Foundation prior + native covariate API + calibrated quantile head, all in one 200 M-param artifact. Chronos was the closest competitor but lacks forecast_with_covariates() and uses sampling-based quantiles. ARIMAX (status quo) cold-starts to global mean and produces 6,700 unmonitorable artifacts. LLMs are wrong tool — tokenization of real numbers is lossy, no calibrated probabilities, 100× cost.
Why LoRA over full fine-tuning?
Three reasons. (1) Cost: LoRA r-8 captures >85% of the achievable accuracy gain at <1% of full FT compute (~$7/qtr vs ~$45K). (2) Storage: 4 MB per family vs 800 MB. (3) Catastrophic-forgetting protection: frozen trunk preserves the foundation prior on long-tail OD-pairs that don't see fine-tune examples.
Walk me through the 47× inference speedup.
Batching first — 80% of the win. 280 ms → 18 ms by going from batch=1 to batch=64 (better tensor-core utilization). Then BF16 (2×), torch.compile with reduce-overhead mode (1.5×, eliminates kernel-launch overhead via CUDA graphs), and pinned-memory LoRA hot-swap (~8 ms instead of 800 ms). Each layer is independently rollback-able.
How do you know your 80% prediction intervals are calibrated?
Two checks in CI gate. (1) Empirical coverage: fraction of actuals between q10 and q90 should be ~80%; ours is 79.3%. (2) Expected Calibration Error (ECE): sum of |empirical - nominal| across 9 quantile bins. Release blocks if coverage drifts outside [78%, 82%] or ECE > 0.04.
Walk me through your 2 a.m. coverage-drift response.
First 30 s: open Datadog dashboard, find which family is red. 30s–90s: check covariate PSI — if any covariate red, it's upstream. 90s–3 min: if upstream, mark feature stale and re-score the family. 3–5 min: if not upstream, roll back the family's LoRA via aa_pricing_cli rollback --stage lora --family X. Investigation next morning. Runbook says explicitly: do NOT debug at 2 a.m.
How does TimesFM know it's Thanksgiving on Nov 27?
It doesn't — not from history. The holiday_flag covariate explicitly tells it. The XReg head learned that flag=2 means +$87 on the median. The covariate is a known-future input, populated months ahead by the pricing team. This is the value of covariate-conditioning: known structure feeds directly in.
How is the fuel coefficient validated?
Cross-validated against the OR team's independent bottom-up calculation: average fuel burn per passenger-mile, hedging policy (35%), pass-through ratio (60%) → expected $11.0/$1. Our learned coefficient: $11.4. Within 4%. The cross-validation against domain knowledge is one of the strongest sanity checks an Applied Scientist can do.
Why isn't competitor matching done explicitly?
Two reasons. (1) Antitrust risk: explicit "match Delta exactly" rules are visible in artifacts and create regulatory exposure. (2) Loyalty math: ~28% of hub-corp bookings are AAdvantage / corp contracts; they'll pay an AA premium. Explicit matching leaves money on the table. The model produces an expected fare given competitor moves; the optimizer applies a conservative buffer ($3 on hub, $5 on leisure, $1 on event-leisure).
Why train weather covariates on scheduled flags, not realized outcomes?
Feedback loop. If trained on realized irrops, lower forecasts → lower bid-prices → cheaper sold seats → lower realized fares → more negative coefficient on next retrain. The coefficient amplifies. Training on the day-ahead scheduled flag breaks the loop — coefficient measures expected effect of predicted irrops, not realized fare collapse.
How do you forecast a brand-new OD-pair with zero history?
Synthetic-prior bootstrap. Build a 90-day context by averaging normalized fare curves from analog routes (e.g., for JFK-PVG: JFK-HKG, JFK-NRT, ORD-PVG). Scale by the new route's base fare. Run forecast_with_covariates() on synthetic context + real AA covariates. Inflate q10/q90 PIs by 30% to reflect the synthetic context's reduced informativeness. Tapers to 0 inflation as real history accumulates over 90 days.
Why is the premium-economy PI 4× wider than main cabin?
Three drivers learned from history: (1) smaller sample — ~30 seats vs ~150, daily averages noisier. (2) Customer mix — corporate / last-minute upsell / schedule-driven, less predictable than vacationing main cabin. (3) Wider price discrimination — 6 fare classes spanning $700 vs 10 classes spanning $200. The wider PI is calibrated and correct — pretending otherwise would have the optimizer over-protect.
How did you go from Applied Scientist to shipping production ML?
Picked up the pieces ML Engineering would normally own — Airflow DAGs, eval-as-code with CI gates, signed model artifacts, runbooks, on-call rotation. The mindset shift: stop optimizing for "the notebook works" and start optimizing for the failure modes I'd have to debug at 2 a.m. The technical work is the same; the operational discipline is new.

Decision rules I apply by reflex

When to use a foundation TS model

  • Long-tail / cold-start matters (>10% of series have <90 days)
  • You need probabilistic output (PI bands)
  • You have known-future covariates (holidays, schedules)
  • Operational simplicity matters (one artifact)

When NOT to use a foundation TS model

  • <100 series — per-series fits are fine
  • Real-time serving <10ms (foundation models are too slow)
  • Hard interpretability constraints (regulatory)
  • Multivariate joint forecasting (TimesFM is univariate-conditional)

When to use LoRA

  • You have budget <1% of full FT
  • You need many small adapter variants (per-family, per-tenant)
  • You want hot-swap at inference
  • You need to preserve foundation prior

When to use full fine-tuning

  • You have budget and your team can audit 200M+ param diff
  • One unified model for one well-defined domain
  • Last 0.5 pp of accuracy is worth >100× cost

When to add a covariate to the XReg head

  • It's known for the entire forecast horizon
  • It's available in the live feature store at 02:00 CST
  • It has theoretical (domain) justification
  • SHAP / coefficient stability holds out of sample

When to fall back vs page

  • Adapter load failure → fall back to head-only (graceful)
  • Coverage <75% on top-50 family for 3 nights → page
  • Nightly batch >180s wall time → page
  • Single-night MAPE excursion (holiday) → do not alert

Glossary — key terms in one line

OD-pair
Origin-Destination flight pair, e.g., DFW-LAX. The unit of forecasting.
RMS
Revenue Management System — the C++ optimizer that turns forecasts into bid-prices.
Bid price
The minimum fare at which RMS is willing to sell one more seat in a given fare class.
DTD
Days to Departure. The booking-curve clock; closer = inventory thinning = higher fare.
Load factor
% of seats sold. Lagged 7-day load factor is a demand-momentum proxy.
Irrops
Irregular operations (weather, mechanical). Triggers cancellations and re-accommodation.
Sabre PSS
Passenger Service System — the booking transaction backbone AA reads from.
ATPCO
Industry consortium for fare filings. Source of competitor fare data.
Patching (TimesFM)
Grouping every 32 input points into one transformer "token". Reduces sequence length 32×.
XReg
TimesFM's "exogenous regression" layer: regression on residuals to incorporate covariates.
LoRA
Low-Rank Adaptation. W' = W + (α/r)BA. Cheap, mergeable, hot-swappable PEFT.
QLoRA
4-bit base + LoRA. Memory-efficient; not used here because we had VRAM headroom.
BF16
Brain Floating Point 16-bit: same exponent as FP32, fewer mantissa bits. 2× throughput on tensor cores.
Pinball loss
Quantile-regression loss. Minimizing it produces conditional quantiles.
CRPS
Continuous Ranked Probability Score. Generalizes MAE to distributions.
ECE
Expected Calibration Error: deviation of empirical coverage from nominal across quantile bins.
Coverage
Fraction of actuals falling inside the predicted PI. Target 80% for the 80% PI.
PSI
Population Stability Index. Per-covariate distribution-shift detector.
Conformal prediction
Model-agnostic post-hoc PI calibration with finite-sample coverage guarantees.
SLO
Service Level Objective. The target for a metric below which on-call gets paged.
Off-cycle re-score
Mid-day re-run of the forecast triggered by covariate updates above threshold.
Cold-start
Forecasting a series with no history. Solved here by synthetic-prior bootstrap.
Shadow mode
Deploy that produces forecasts but doesn't feed the optimizer — for safe canary testing.
Foundation prior
The implicit knowledge baked into TimesFM's pretraining over 100B time-series points.
fix_quantile_crossing
ForecastConfig flag enforcing q10 ≤ q20 ≤ ... ≤ q90. Required by the optimizer.
